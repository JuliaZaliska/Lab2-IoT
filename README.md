# IoT Telemetry Hub

Вебсервіс для моніторингу IoT-датчиків на різних об'єктах і локаціях. Система відображає поточні показники датчиків, їхній стан та попередження про перевищення заданих порогів. Дані можна переглядати у вебінтерфейсі або отримувати через JSON API за допомогою консольного Python-клієнта.

## Функціональність

### Вебінтерфейс

- Головна сторінка `/` — список датчиків і загальна статистика: кількість датчиків, онлайн/офлайн та кількість активних тривог.
- Пошук за назвою датчика, його типом або назвою локації.
- Фільтрація за локацією та статусом (`online`, `offline`, `maintenance`), а також окремий фільтр активних тривог.
- Сторінка датчика `/sensor/{id}` з його параметрами, порогом тривоги, графіком і переліком інших датчиків тієї самої локації.
- Активна тривога визначається, якщо датчик має статус `online`, для нього задано поріг, а поточне значення дорівнює порогу або перевищує його.

> Графік на сторінці датчика демонструє сформовану на основі поточного значення приблизну динаміку за 12 годин. Історичні вимірювання окремо в базі даних не зберігаються.

### Адміністративна панель

Адмінпанель доступна за адресою `/admin` після авторизації. Вона реалізована за допомогою EasyAdmin і містить CRUD-інтерфейси для:

- **Датчиків** — створення, перегляд, редагування та видалення датчиків; налаштування типу, поточного значення, одиниці виміру, порогу тривоги, статусу та локації.
- **Локацій** — керування назвою, зоною/корпусом та описом локації.

Доступ до `/admin` обмежений роллю `ROLE_ADMIN`. Вхід виконується через форму за адресою `/login`.

### JSON API

API доступне без авторизації та повертає дані у форматі JSON.

| Метод | Endpoint | Опис |
|---|---|---|
| `GET` | `/api/sensors` | Список датчиків із підтримкою фільтрів |
| `GET` | `/api/sensors/{id}` | Детальна інформація про датчик за ID |

Для `/api/sensors` доступні query-параметри:

| Параметр | Призначення | Приклад |
|---|---|---|
| `q` | Пошук за назвою датчика, типом або назвою локації | `?q=temperature` |
| `location` | Фільтр за ID локації | `?location=1` |
| `status` | Фільтр за статусом | `?status=online` |
| `alerts` | Показати лише активні тривоги (`1`) | `?alerts=1` |

Параметри можна комбінувати, наприклад: `/api/sensors?q=CO2&status=online&alerts=1`.

Відповідь списку містить `count` та масив `items`. Об'єкт датчика містить ID, назву, тип, поточне значення, одиницю виміру, поріг тривоги, ознаку `isAlert`, статус, час оновлення та вкладені дані локації. Якщо датчик із заданим ID не знайдено, API повертає HTTP `404`.

### Python-консольний клієнт

Клієнт розташований у каталозі `client/` і використовує бібліотеку `requests`. Він дозволяє:

1. Отримати список усіх датчиків через JSON API.
2. Отримати лише датчики з активними тривогами.
3. Переглянути деталі датчика за ID.
4. Перевірити вхід до адмінпанелі через вебсесію: клієнт отримує CSRF-токен зі сторінки входу, надсилає облікові дані та перевіряє доступ до `/admin`.

За замовчуванням клієнт звертається до `http://127.0.0.1:8000`.

## Технології

- PHP `>= 8.4`
- Symfony `8.1`
- Doctrine ORM та Doctrine Migrations
- SQLite (локальна конфігурація бази даних)
- Twig
- EasyAdmin `5.10`
- Symfony Security (форма входу, хешування паролів, роль `ROLE_ADMIN`)
- Python 3 та `requests`
- Bootstrap 5 та Chart.js для інтерфейсу й графіків

## Встановлення та запуск

### 1. Вимоги

Перед початком роботи встановіть:

- PHP 8.4 або новішої версії з розширеннями, необхідними Symfony та SQLite (`pdo_sqlite`);
- Composer;
- Symfony CLI (для команди `symfony serve`);
- Python 3 (для консольного клієнта).

### 2. Клонування репозиторію та встановлення PHP-залежностей

```bash
git clone https://github.com/JuliaZaliska/Lab2-IoT.git
cd Lab2-IoT
composer install
```

### 3. Налаштування бази даних

Створіть локальний файл `.env.local` у корені проєкту (він не повинен потрапляти до Git) і задайте SQLite-підключення:

```dotenv
DATABASE_URL="sqlite:///%kernel.project_dir%/var/data.db"
```

Переконайтеся, що PHP має увімкнене розширення `pdo_sqlite`.

### 4. Створення таблиць

Таблиці створюються Doctrine Migrations, вручну виконувати SQL-запити не потрібно:

```bash
php bin/console doctrine:migrations:migrate
```

### 5. Створення адміністратора

Виконайте консольну команду, передавши email і пароль адміністратора:

```bash
php bin/console app:create-admin admin@example.com "ВАШ_НАДІЙНИЙ_ПАРОЛЬ"
```

Команда створює користувача з роллю `ROLE_ADMIN` і зберігає хеш пароля. Використовуйте власні облікові дані; не додавайте пароль до файлів проєкту, README або Git-репозиторію.

### 6. Додавання демонстраційних даних (необов'язково)

Для заповнення бази тестовими локаціями та датчиками виконайте:

```bash
php bin/console app:seed-iot
```

Команда додає 3 локації та 8 датчиків із різними значеннями, статусами й порогами тривоги.

### 7. Запуск вебсервера

```bash
symfony serve
```

Після запуску відкрийте адресу, яку покаже Symfony CLI (типово `https://127.0.0.1:8000` або `http://127.0.0.1:8000`).

- Головна сторінка: `/`
- Вхід: `/login`
- Адмінпанель: `/admin`
- JSON API: `/api/sensors`

### 8. Запуск Python-клієнта

У новому терміналі з кореня проєкту:

```bash
python -m venv .venv
```

Активуйте віртуальне середовище:

**Windows PowerShell:**

```powershell
.venv\Scripts\Activate.ps1
```

**Linux / macOS:**

```bash
source .venv/bin/activate
```

Встановіть залежності та запустіть клієнт:

```bash
pip install -r client/requirements.txt
python client/client.py
```

У меню клієнта виберіть потрібну дію. Для перевірки входу до адмінпанелі використовуйте email і пароль створеного адміністратора.

## Структура проєкту

```text
src/
├── Command/       # Команди створення адміністратора та тестових даних
├── Controller/    # Контролери вебсторінок, API та авторизації
│   └── Admin/     # EasyAdmin Dashboard і CRUD-контролери
├── Entity/        # Doctrine-сутності
└── Repository/    # Запити до бази даних

migrations/        # Doctrine migrations
 templates/        # Twig-шаблони
client/            # Python-консольний клієнт
config/            # Конфігурація Symfony
```

## Модель даних

Основні сутності предметної області:

- **Location** — локація або об'єкт, на якому встановлено датчики. Містить назву, зону/корпус та опис.
- **Sensor** — IoT-датчик із назвою, типом, поточним значенням, одиницею виміру, порогом тривоги, статусом і часом останнього оновлення.

Зв'язок між сутностями: одна `Location` може містити багато `Sensor` (`OneToMany`), а кожен `Sensor` належить одній `Location` (`ManyToOne`). Додатково сутність `User` використовується для зберігання облікових записів адміністраторів.

Структура таблиць створюється файлами міграцій у каталозі `migrations/`.

## Безпека та файли, які не потрібно комітити

Не додавайте до репозиторію:

- `.env.local` та інші локальні файли конфігурації із секретами;
- `vendor/`;
- локальну базу даних та інші приватні дані;
- паролі, токени й приватні ключі.

Для відтворення проєкту інший розробник має клонувати репозиторій, встановити залежності, налаштувати власне підключення до бази даних, виконати міграції та створити власний обліковий запис адміністратора.
